## 4. 회의록 작성 가이드

### 4.1 좋은 회의록의 조건

1. **결정사항이 명확하다**: "논의함" X. "X를 Y로 결정함" O.
2. **담당자와 마감이 있다**: 모든 액션 아이템에 누가 / 언제.
3. **다음 회의에서 검증된다**: 액션 아이템 결과를 체크.
4. **불참자가 읽고 따라잡을 수 있다**: 맥락 포함.

### 4.2 작성 시점

- **즉시**: 회의 중 서기가 실시간 타이핑
- **마감**: 회의 종료 후 1시간 내 디스코드 #docs 채널에 공유
- **확정**: 24시간 내 이의 없으면 확정

### 4.3 보관

- 위치: `docs/05_관리/회의록/` 폴더
- 파일명: `회의록_YYYY-MM-DD.md` (정렬 위해 YYYY-MM-DD 형식 고정)
- Git에 커밋 (코드와 함께 버전 관리)

### 4.4 권장 회의 시간

| 회의 종류 | 권장 시간 | 비고 |
|---|---|---|
| 주간 회의 (화/금) | 30분 | 길어지면 안건 분리 |
| 데일리 스탠드업 | 비동기 (텍스트) | 음성 X |
| 애드혹 | 15분 이내 | 단일 결정만 |
| 회고 (스프린트 종료) | 60분 | 격주 |
| 발표 리허설 | 90분 | W4 |

### 4.5 회의 안 해도 되는 경우

다음은 회의 대신 디스코드 텍스트로 처리:
- 단순 진척 공유 → 데일리 스탠드업
- 1:1 대화 → DM
- 코드 리뷰 → GitHub PR
- 명세 질문 → 해당 PR 또는 이슈
